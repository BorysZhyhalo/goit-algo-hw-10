# Домашнє завдання 1 — Касова система (решта монетами)

## Опис

Програма для касового апарату, яка визначає, як видати решту монетами набору `[50, 25, 10, 5, 2, 1]`.

Реалізовано дві функції в `main.py`:

1. **`find_coins_greedy`** — жадібний алгоритм (бере найбільші номінали спочатку).
2. **`find_min_coins`** — динамічне програмування (мінімальна кількість монет).

## Запуск

```bash
python main.py
```

Після запуску:

- показуються приклади (сума `113` і контрприклад);
- можна ввести свою суму;
- опційно — benchmark для великої суми (`100000`).

## Приклади

### Сума 113 (з умови)

| Алгоритм | Результат |
|----------|-----------|
| Greedy | `{50: 2, 10: 1, 2: 1, 1: 1}` |
| DP | `{50: 2, 10: 1, 2: 1, 1: 1}` |

Обидва алгоритми дають **5 монет** — для цього набору номіналів greedy також оптимальний.

### Контрприклад (коли greedy не оптимальний)

- Монети: `[1, 3, 4]`
- Сума: `6`
- Greedy: `4 + 1 + 1` → **3 монети**
- DP: `3 + 3` → **2 монети**

## Порівняння алгоритмів

| Критерій | Greedy | Dynamic Programming |
|----------|--------|---------------------|
| Час (Big-O) | `O(k)` | `O(amount * k)` |
| Пам'ять | `O(1)` | `O(amount)` |
| Оптимальність | Не завжди мінімум монет | Завжди мінімум монет |
| Швидкість на великих сумах | Дуже швидкий | Повільніший при зростанні `amount` |

де `k` — кількість номіналів, `amount` — сума решти.

## Результати benchmark (сума 100 000)

Порівняння виконано командою `python main.py` з увімкненим benchmark (`y`).

| Показник | Greedy | Dynamic Programming |
|----------|--------|---------------------|
| Розклад монет | `50 x 2000` | `50 x 2000` |
| Загальна кількість монет | 2000 | 2000 |
| Час виконання | **0.000013 с** | **0.045258 с** |

**Співвідношення швидкості:** greedy приблизно у **~3500 разів** швидший за DP на цій сумі.

Обидва алгоритми дали **однаковий оптимальний результат** для набору `[50, 25, 10, 5, 2, 1]`: 2000 монет по 50 = 100 000.


--- Порівняння для суми 100,000 ---
Greedy: 50 x 2000 | монет: 2000
DP:     50 x 2000 | монет: 2000
Час Greedy: 0.000013 с
Час DP:     0.045258 с


## Висновки

1. **Greedy** простий і швидкий: один прохід по номіналах (`O(k)`).
2. **DP** повільніший на великих сумах (`O(amount × k)`), бо будує таблицю розміром `amount + 1`.
3. Для `[50, 25, 10, 5, 2, 1]` обидва алгоритми дають **однаковий оптимальний результат** (перевірено на сумах `113` і `100 000`).
4. На benchmark `100 000` greedy виконався за ~0.000013 с, DP — за ~0.045 с; для каси з фіксованими номіналами greedy практичніший.
5. На «нестандартних» номіналах (наприклад `[1, 3, 4]`, сума `6`) greedy може помилятися — DP надійніший і завжди знаходить мінімум монет.

## Тестування (касова система)

1. Запустити `python main.py`.
2. Перевірити вивід для суми `113` — обидва алгоритми: `{50: 2, 10: 1, 2: 1, 1: 1}`, 5 монет.
3. Ввести `0` — очікується порожній результат.
4. Запустити benchmark (`y`) для суми `100 000`:
   - очікуваний розклад: `50 x 2000`;
   - greedy швидший за DP (орієнтовно < 0.0001 с проти ~0.04–0.05 с).
